# Mihomo 订阅与固定节点出口

此功能在 `stl25/vm2api` 的 `codex/mihomo-proxy-management` 分支维护，不依赖旧管理员修复 PR。

## 使用

管理员打开 **代理 → Mihomo 订阅**：

1. 点击**安装并启动**；默认 `latest` 从官方发行接口获取最新稳定版，也可填写 `v` 开头的稳定版本号。支持 Linux amd64/arm64，下载后按官方 SHA-256 校验，并确认该版本可加载现有节点配置，安装完成后启动并保存自启动状态。
2. 添加 Clash/Mihomo YAML 订阅，或 HTTP(S)/SOCKS5 动态代理。只读取订阅的 `proxies`，不导入其监听器、规则、控制器或链式代理配置。
3. 确认内核运行中。选择节点，测试连接或基础网络质量，再添加到现有代理池。
4. 在代理池中将节点绑定到**本机槽位**；OAuth、刷新和推理沿用该槽位的代理出口。远程集群槽位不能使用控制面的回环监听器。

版本栏显示实际安装版本，**检查更新**获取官方最新稳定版。更新前先停止内核，再点击**更新并启动**；`KIN_MIHOMO_BIN` 指定的内核由部署者更新。安装面板显示下载字节、百分比、校验、安装和启动阶段。启动失败会明确提示“已安装但启动失败”，可修正配置后点击启动；重新打开页面也可查看进行中的安装状态。

订阅支持独立改名、更新地址、刷新、启停和删除。更新失败保留旧缓存；多个来源共享的节点在其他来源仍保留时继续存在。节点 ID 根据连接配置生成，改名不改变绑定；端点或凭据改变视为新节点，旧绑定不自动改指新节点。

代理页的 **Mihomo 订阅** 按钮显示展开/收起文字与方向箭头；展开时使用选中样式。收起仅隐藏面板，保留未保存的来源表单、筛选和选择，继续已开始的批量检测。离开代理页会停止尚未开始的检测。代理池后台刷新失败时保留已有面板和草稿，标明当前显示上次数据，并提供重试入口。

## 出口契约

- 每个加入代理池的节点对应持久化、带认证的本地 SOCKS5 端口，只监听 `127.0.0.1`；不同槽位可以同时绑定不同节点。
- 节点停用、来源移除或内核停止后，旧出口拒绝请求，不改为其他节点或直连。停用时关闭该节点已有连接；其他节点保持不变。
- 出口恢复后，首次成功健康探测恢复因该出口故障而停用的槽位；保留手动停用和其他故障原因。代理池名称作为持久化别名，不被来源刷新覆盖。
- 已绑定槽位的节点不可从代理池删除；先解除绑定。删除后端口仍预留给原节点，不分配给另一个节点。
- **固定节点不等于固定公网 IP。**动态代理供应商仍可能为每次连接分配不同公网 IP。
- 普通 SOCKS5 代理和每台 VPS 的本机出口保持原行为；此功能不修改系统代理，也不提供 BPS 调度或自动换出口。

## 下载与检测

下载模式只影响订阅：`direct` 明确直连，`proxy` 只走运行中的 Mihomo，`auto` 先代理、失败再直连。首次没有内核时，自动模式使用直连；自动回退可能向订阅提供方暴露服务器 IP。

连接及质量检测使用独立单节点内核，最多同时四个，不修改业务内核配置、节点启停状态或槽位绑定。质量显示常见 HTTPS 站点的通过数量与出口位置，未取得地区信息的节点不推断地区；页面按实测结果筛选。每次检测替换上次结果，失败不沿用旧 IP 或质量数据。批量动作只作用于当前筛选中勾选的节点，可一键选择全部筛选结果或清空选择；本页部分选中时显示半选状态。加入代理池前，需先启用或取消选择停用节点。批量检测显示进度，可停止尚未开始的检测；已开始的检测完成后保留结果。检测结果仅保存在内存，重启后清空。

完整订阅地址和节点凭据不出现在列表、错误响应或内核日志中。管理员的显式“复制代理”沿用原有授权接口，复制的是本机认证监听地址，不是订阅节点密钥。

## 配置、恢复和回滚

数据保存在 `data/mihomo/settings.json`，权限为 `0600`；内核和运行配置也位于该私有目录。面板备份包含这份配置及其校验值；没有 tar 时，数据库压缩备份也保存配置快照。恢复期间拒绝管理与业务请求，等待进行中的检测结束，停止旧内核，再恢复配置、代理池和自启动状态。缺少 Mihomo 配置但含托管代理的旧备份会被拒绝，请改用完整目录备份。不能仅导出普通代理 URL。新增代理使用保留的 `px-mh-` ID，不改变数据库结构。

启动等待内核完成监听配置应用，而不只检查控制接口。手动启动后重启控制面会恢复内核；手动停止后不会自启动。停止操作等待旧内核真正退出并释放端口；控制面关闭时取消未完成的内核安装和启动，不在关闭后写入新的自启动配置。升级前保存旧镜像、Compose 配置及 `data`、`vms`、`bin`、`share`、`src/config` 的一致性备份。回滚应一起恢复镜像和部署前数据，不能只切回不认识 Mihomo 绑定的旧代码。

接口字段、动作与错误说明见 [面板 API](PANEL_API.md#mihomo仅-admin)，安装环境与私有数据目录说明见 [部署文档](DEPLOY.md#mihomo-订阅与节点出口可选)。

```sh
node --test test/unit/mihomo.test.mjs test/unit/mihomo-regressions.test.mjs test/unit/backup-service.test.mjs
KIN_MIHOMO_INSTALL_SMOKE=1 node --test test/e2e/mihomo.e2e.test.mjs
```

真实内核测试使用两个本机模拟出口，不使用生产订阅、不调用模型，覆盖独立转发、并发、停用拒绝、刷新和重启恢复。CI 继续执行现有 Node、前端、Go、payload 和 ARM64 检查，并加入真实 Mihomo 与备份恢复回归。
