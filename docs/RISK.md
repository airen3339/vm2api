# 封控拦截

请求在选槽、出站之前先过一道闸。`/v1` 和 `count_tokens` 共用。拦住就不 hop，不消耗上游额度。管理台入口是「风险审计」（`/console/#/risk`）。

顺序固定，便宜的规则在前，模型在最后，不能调换。

## 五道关

| 顺序 | 关 | 扫什么 | 拦住 |
|------|----|--------|------|
| 1 | 蒸馏 | 收割模板、题目指纹、结构特征 | 默认 403，并封 device |
| 2 | 硬正则 | 直接用户文本上的类别正则 | 400，不进槽；蒸馏类沿用蒸馏关状态 |
| 3 | 拒答缓存 | 上游拒过的正文、近似正文、已封 device | 403 |
| 4 | 决策模型 | 安全模型逐题打分 | 低于阈值则 400 |
| 5 | 放行出站 | 前面都没拦的请求 | 进入槽位 |

「放行出站」不是第六道闸。它同时列出两类没被闸拦住、但结果仍异常的请求：决策模型打分失败后的放行，以及上游自己的拒答。用来看漏拦。

## 蒸馏

总开关默认开。OpenAI 平台模型整段跳过，不扫针、指纹，也不扫蒸馏类正则。

检测器（针、指纹、结构收割）默认再跳过官方 Claude Code 和 0 注入。这是 `skip_official` / `skip_zero`，面板可关。

硬正则里的 distill 类别不看这两个跳过。关掉硬正则总开关仍然拦这些短语；只有关掉蒸馏总开关才放行。官方客户端和 0 注入仍扫。OpenAI 不扫。

命中返回蒸馏关配置的 HTTP 状态，默认 403，文案默认「不允许蒸馏」，并封这次请求的 device。

单独的思考标签不是蒸馏。要拦的是要求「按该格式作答」的收割模板。

## 硬正则

类别：色情、蒸馏、破解、破限、自定义。蒸馏类见上一节，其余跟硬正则总开关。命中返回 400 `invalid_request_error` / `policy_blocked`，带 `details.retryable=false` 和 `x-should-retry: false`，不写入拒答缓存。真正的鉴权错误和上游拒答保留原状态。

硬正则和决策模型扫描当前及历史的直接用户文本。`tool_result`、其他工具输出及 assistant / system 内容属于上下文数据，不作为用户指令扫描；直接用户文本中的真实规则命中仍会拦截。

附加正则和内置规则一起扫。`rules: []` 与 `rules: null` 都回落内置规则；关掉这一层用硬正则总开关。扫描前默认去掉常见提醒，并展开正文里的 base64；这两项可关。比较的是用户自己写下的正文，不含 user 轮里的 `tool_result` / `*_tool_result` / `function_call_output`。

## 拒答缓存

只记上游真正拒过的正文。硬正则和决策模型自己打回的拦截不进这张缓存，下次仍重新过闸。

三种命中都是不可自动重试的 403 `permission_error` / `refusal_guard`，响应带 `details.retryable=false` 和 `x-should-retry: false`：

- 精确指纹
- 近似正文（默认相似度 0.9，面板可调；近似仍把工具回传算进文档）
- 已封禁的 device

`details.blocked_by` 分别为 `exact`、`similar`、`device`。设备命中另带合法的来源请求 UUID。设备封禁开启时，同一设备的不同正文也会被拦；只关闭「device 封禁」可恢复正常新请求，并保留原拒答指纹及近似正文拦截。真实上游 Usage Policy 拒答返回同一 403 契约，`blocked_by=upstream`。

## 决策模型

最后一道。把整理后的直接用户文本以及客户端 `system` / `instructions` 交给配置的安全模型，逐题打分。低于阈值才拦，返回 400 `invalid_request_error` / `policy_blocked`。

只有一道题落在阈值下方 0.08 以内时不拦。两道题都低于阈值，或一道题明显更低，仍然拦。同一段正文在去重窗口内复用上一次结论。

模型不可用时默认放行，风险审计里记为「模型故障放行」。关掉失败放行后，模型不可用则拦。401 / 429 / 529 会换下一把密钥再试。

没配模型地址时，这道闸等于没接上，不要当成已经在保护账号。

## 日志

每条请求记下过了哪一关、命中词和规则。升级前没有这条记录的旧日志，在风险审计里显示为「未经关卡」。

被放行的正常请求在「日志」，不在拦截流水里。误伤时收紧或关掉对应的关，不要删槽。这一页上未保存的修改，离开时会丢掉。
